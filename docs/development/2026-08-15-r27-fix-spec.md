- 日期：2026-08-15
- 状态：已实现，测试已绿
- 范围：`loomq-core` 命令副作用 / 启动标志可见性 / 文档

## 1. 背景

第六轮审计发现以下问题。

| # | 问题 | 严重度 | 验证测试 |
|---|------|--------|----------|
| 1 | `createIntent` 在重复创建被拒前就归一化 `precisionTier`，会修改调用方传入的 Intent | 中 | `BugRejectedCommandMustNotNormalizeTierTest#duplicateCreateRejectionMustNotMutatePrecisionTier` |
| 2 | `updateIntent` 在校验失败前就归一化 `precisionTier`，校验失败也会修改内部状态 | 中 | `BugRejectedCommandMustNotNormalizeTierTest#failedUpdateValidationMustNotNormalizePrecisionTier` |
| 3 | `LoomqEngine.retryUnsupported` 非 volatile，跨线程可见性无保证 | 低 | 代码审查 |
| 4 | `LoomqEngine` catch 注释仍写“直接置 closed”，与实际不符 | 低 | 文档修正 |

---

## 2. 修复设计

### 2.1 归一化时机后移

**文件**：`IntentCommandService`

- `createIntent`：将 `normalizePrecisionTier(intent)` 移到 `hasActiveDuplicate` 检查之后。
- `updateIntent`：将 `normalizePrecisionTier(intent)` 移到 `IntentValidator.validate(intent)` 之后。

这样被拒绝的命令不会因为归一化而修改调用方对象。

### 2.2 `retryUnsupported` 改为 volatile

**文件**：`LoomqEngine`

```java
private volatile boolean retryUnsupported = false;
```

### 2.3 修正 catch 注释

**文件**：`LoomqEngine`

将“直接置 closed”改为“标记 retryUnsupported，禁止重试但保留 close() 清理能力”。
