- 日期：2026-08-15
- 状态：已实现，测试已绿
- 范围：`loomq-core` 背压指标 / 调度器生命周期 / trace 可观测性 / 引擎重试安全

## 1. 背景

第四轮审计确认以下问题，并连同前几轮遗留问题一起处理。

| # | 问题 | 严重度 | 验证测试 |
|---|------|--------|----------|
| 1 | 背压状态/指标未统计跨档借用的在途投递 | 中 | `BugBackpressureIgnoresBorrowedTest` |
| 2 | `pendingScanTrigger` 在 `start()` 时未清空 | 低 | `BugPendingScanTriggerNotClearedOnStartTest` |
| 3 | `DeliveryResult.RETRY` / `DEAD_LETTER` 结果路径未记录 trace failure | 低 | `BugTraceFailureNotRecordedOnResultPathTest` |
| 4 | `LoomqEngine.start()` 在 daemon 部分启动后仍允许重试，实际会失败 | 中 | 代码审查 |

## 2. 失败测试

### 2.1 `BugBackpressureIgnoresBorrowedTest`

- 场景：ULTRA max=1，占用 own permit 后从 FAST 借用 1 个 permit，并模拟 2 个在途。
- 期望：`activeDispatches == 2`。
- 修复前：`activeDispatches == 1`。

### 2.2 `BugPendingScanTriggerNotClearedOnStartTest`

- 场景：`stop()` 后手动设置 `pendingScanTrigger[STANDARD]=true`，再 `start()`。
- 期望：标志被清空（false 或 entry 不存在）。
- 修复前：标志仍为 true。

### 2.3 `BugTraceFailureNotRecordedOnResultPathTest`

- 场景：DeliveryHandler 返回 `RETRY`。
- 期望：trace 中 `failureReason` 不为 null。
- 修复前：`failureReason == null`。

---

## 3. 修复设计

### 3.1 背压状态使用 `tierInFlight`

**文件**：`PrecisionScheduler`

- `isTierUnderBackpressure()` 改为以 `tierInFlight >= maxConcurrency` 判断并发耗尽。
- `getBackpressureStatus()` 的 `activeDispatches` 改为 `tierInFlight.get(tier).get()`。

### 3.2 `start()` 清空 `pendingScanTrigger`

**文件**：`PrecisionScheduler`

在 `start()` 中：

```java
pendingScanTrigger.clear();
```

### 3.3 结果路径记录 trace failure

**文件**：`PrecisionScheduler`

在 `finalizeIntent` 中：

- `RETRY` 分支：`traceStore.recordFailure(..., "RETRY", null)`
- `RETRY` 达到 maxAttempts 的死信分支：`traceStore.recordFailure(..., "DEAD_LETTER", null)`
- `DEAD_LETTER` 分支：`traceStore.recordFailure(..., "DEAD_LETTER", null)`

### 3.4 `LoomqEngine.start()` 重试安全

**文件**：`LoomqEngine`

- 新增 `daemonsStarted` 标志。
- 在 `commitBarrier.start()` 成功后置 true。
- 若 `start()` 失败且 `daemonsStarted == true`，直接 `closed.set(true)`，禁止不安全重试。
- 若失败发生在 recovery 阶段（daemon 未启动），仍允许重试。
