# R26 修复 Spec：第五轮迭代自审修正

- 日期：2026-08-15
- 状态：已实现，测试已绿
- 范围：`loomq-core` 启动失败清理 / 注册与 flush 竞态

---

## 1. 背景

第五轮迭代对前一轮改动进行自审，发现两个需要修正的问题。

| # | 问题 | 严重度 | 验证测试 |
|---|------|--------|----------|
| 1 | R25 在 start 失败后直接 `closed.set(true)`，导致 `close()` 无法清理 operationExecutor 等资源 | 中 | `BugEngineRetryUnsupportedAfterDaemonStartTest` |
| 2 | `CohortManager` / `PromotionDaemon` flush 时无条件移除 mapping，可能误删并发 re-register 到新 cohort 的映射 | 低 | 代码审查 |

---

## 2. 修复设计

### 2.1 `LoomqEngine` 启动失败后保留 close 能力

**文件**：`LoomqEngine`

- 新增 `retryUnsupported` 标志。
- `start()` 开头如果 `retryUnsupported == true`，直接抛 `IllegalStateException`。
- `start()` 失败且 daemon 已启动时，设置 `retryUnsupported = true`，**不再设置 `closed = true`**。
- 这样调用方仍然可以调用 `close()` 完成资源清理。

### 2.2 `CohortManager` / `PromotionDaemon` 条件移除 mapping

**文件**：

- `CohortManager.wakeLoop`
- `PromotionDaemon.tickOnce`

flush 旧 cohort 时，只在 `intentIdToCohortKey` 仍指向当前 cohort 时才移除：

```java
Long currentKey = intentIdToCohortKey.get(intentId);
if (currentKey != null && currentKey.equals(bucketKey)) {
    intentIdToCohortKey.remove(intentId, currentKey);
}
```

避免误删并发 re-register 到新 cohort 的映射。
