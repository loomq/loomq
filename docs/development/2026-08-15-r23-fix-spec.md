## 2. 失败测试

### 2.1 `BugStoreCountDriftAfterPostCommitFailureTest`

- 场景：`UpdateThrowingStore.update()` 抛错，`updateIntent` 将 SCHEDULED 更新为 DUE 并返回成功。
- 期望：`countByStatus(SCHEDULED)==0`，`countByStatus(DUE)==1`。
- 修复前：`SCHEDULED==1`，`DUE==0`。

### 2.2 `BugGroupCommitBarrierCloseBeforeStartTest`

- 场景：`GroupCommitBarrier` 构造后未 `start()` 直接 `close()`。
- 期望：`inlineForceExecutor.isShutdown()==true`。
- 修复前：`false`。

### 2.3 `BugIntentTraceNullTierTest`

- 场景：构造 `IntentTrace` 时 `tier=null`，调用 `toJson()`。
- 期望：不抛异常。
- 修复前：NPE。

## 3. 修复设计

### 3.1 提交后内存计数补偿

**文件**：

- `IntentCommandService.updateIntent`
- `PrecisionScheduler.updateStoreBestEffort`

**做法**：

当 `IntentStore.update()` 失败但持久化已提交时，追加一次 best-effort `intentStore.save(intent)`，尽量让 `ConcurrentIntentStore` 的 `statusCounts` / `pendingCount` 与 live 状态一致。

若 `save()` 也失败，仅记录 warn，不阻断主流程。

### 3.2 `GroupCommitBarrier.close()` 资源释放

**文件**：`GroupCommitBarrier`

**做法**：

`close()` 不再因 `running` 为 false 而提前 return。无论是否曾启动，都：

- 尝试 interrupt / join daemon 线程；
- shutdown `inlineForceExecutor`。

### 3.3 `IntentTrace.toJson()` null tier 防御

**文件**：`IntentTrace`

**做法**：

```java
tier != null ? tier.name() : "UNKNOWN"
```

### 3.4 `IntentTraceStore` eviction queue 动态容量

**文件**：`IntentTraceStore`

**做法**：

`EvictionQueue` 容量由构造参数决定：

```java
new EvictionQueue(Math.max(maxSize + 10_000, 1))
```

### 3.5 注册幂等

**文件**：

- `CohortManager.register`
- `PromotionDaemon.register`

**做法**：

注册前先按 `intentId` 摘除旧 cohort 条目，再写入新条目，避免重复注册导致旧条目残留。

### 3.6 `recordFailure` 接线

**文件**：`PrecisionScheduler.handleDeliveryException`

**做法**：

在投递异常路径调用：

```java
traceStore.recordFailure(intent.getIntentId(), ex.getMessage(), null);
```

### 3.7 `LoomqEngine.start()` 注释修正

**文件**：`LoomqEngine`

**做法**：

明确只有 recovery 阶段失败可安全重试；daemon 启动后 thread 为一次性，不能承诺任意阶段可重试。
